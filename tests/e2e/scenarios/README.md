# E2E Scenario Matrix

This matrix is the coverage source of truth. Tests may be implemented in
layered suites (`driver-write`, `admin-write`, `payments-accounting`, `gold`),
but scenarios here describe the real-world behavior we need to prove.

Support code should create scenarios and assert outcomes. It should not
reimplement pricing, reconciliation, webhook, or bookkeeping business logic that
belongs to the app.

## Expected Behavior Columns

- **Driver UI**: what the driver should see or be allowed to do.
- **Admin UI / Needs Review**: what an admin should see, including warnings and
  action queues.
- **Audit / Gate**: authoritative gate and audit side effects.
- **DB**: expected session, payment, refund, billing, and disposition state.
- **Stripe**: expected test-mode customer, payment, subscription, invoice, refund,
  dispute, or webhook state.
- **QuickBooks**: expected sales receipt, refund receipt, voided/inactive records,
  or sync failure state.
- **Reconcile**: expected issue codes, severities, suppression, and advanced-tab
  evidence.
- **Cleanup**: how test artifacts are reset, voided, cancelled, or filtered by
  `testRunId`.
- **Suite**: likely first automated home.
